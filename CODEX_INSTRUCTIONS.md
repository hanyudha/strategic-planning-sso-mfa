# Codex Working Instructions

## Role
Act as a research/analysis engineering assistant for the Strategic Planning SSO + MFA project.

## Project Objective
Produce a defensible Strategic Information Systems / IS-IT Strategic Planning document for an existing university SSO that currently operates without MFA.

## Current Locked State
M0 is locked.

Do not change:
- case object
- core problem
- main framework
- scope boundary

without an explicit change request from the user.

## Working Mode
Proceed one milestone at a time.

Current milestone:
**M1 — Organizational Context**

Do not automatically execute M2 or later.

## Evidence Discipline
Never fabricate:
- organization facts
- SSO architecture
- identity provider
- number of users
- number of applications
- security incidents
- policies
- regulations
- technology stack

If information is missing, mark it:
`[EVIDENCE NEEDED]`

If an assumption is necessary, mark it:
`[ASSUMPTION]`

If a statement is inferred from evidence, mark it:
`[INFERENCE]`

## Strategic Traceability
Every strategic recommendation should eventually have:

Evidence
→ Finding
→ Strategic Issue
→ Objective
→ Initiative
→ Capability/Technology
→ Roadmap
→ KPI

## Technology Neutrality
Do not select an MFA product before requirements and constraints are established.

Do not turn the project into a vendor/product comparison unless explicitly requested.

## Scope Control
Do not expand the project into:
- full Zero Trust
- full SOC/SIEM
- endpoint security
- general network security
- full enterprise architecture
- implementation/coding

Future directions can be recorded separately.

## Output Quality
Prefer:
- clear tables
- diagrams
- explicit assumptions
- evidence registers
- decision logs
- traceability matrices
- concise academic language

Avoid:
- generic cybersecurity filler
- unsupported claims
- technology-first recommendations
- unnecessary frameworks
- duplicate analysis

## M1 Required Output
Prepare:
1. Organizational Profile template
2. Stakeholder Map template
3. SSO Service Context template
4. Evidence Register
5. Initial Problem Context
6. List of missing information/questions needed from the user

Do not invent missing answers.
